# uEngine ERP

판매 하나로 시작해 회사가 크는 만큼 모듈을 더하는 ERP입니다. 앱은 무료로 쓰고, 데이터는 내 Supabase 프로젝트에 둡니다. 쓰는 쪽이나 우리나 서버를 따로 운영하지 않습니다.

모든 변경을 이벤트로 쌓기 때문에 어떤 과거 시점이든 그대로 볼 수 있고, 잘못한 작업을 범위를 확인한 뒤 되돌릴 수 있으며, 바꾸기 전에 매출 변화를 시험해 볼 수 있습니다.

## 시작하기

1. [Supabase](https://supabase.com) 프로젝트를 만듭니다. 무료 플랜으로 충분합니다.
2. [앱](https://uengine-oss.github.io/uengine-erp/)을 열고 프로젝트 주소와 공개 키를 넣습니다.
3. 화면이 주는 설치 SQL 을 SQL Editor 에 붙여 넣어 실행합니다.
4. 회사를 만듭니다. 이때 판매 모듈이 켜집니다.

## 모듈

| 모듈 | 하는 일 | 켜면 새로 되는 예측·what-if |
|---|---|---|
| 판매 | 거래처, 제품, 가격표, 견적, 주문 | 지역·제품·시즌 통계, 수요 예측, 단종(범위) |
| 재고 | 창고, 입출고, 재고 조정, 재주문 규칙 | 품절 예상일, 발주 정책 변경, 창고 재배치, 단종(대체율 추정) |
| 구매 | 견적 요청, 구매 주문, 입고 | 실측 납기, 발주 필요 예측, 납기·공급사 변경 |
| 청구 | 청구서, 대변 메모, 입금 | 입금 예측, 결제 조건 변경 |
| 회계 | 분개, 시산표, 손익, 재무상태 | 손익 전망 |
| 인사 | 부서, 직원, 입사와 퇴사, 개인정보(원장 밖, 지울 수 있음) | 인원 추이·입퇴사 |
| 경비 | 영수증 첨부, 상사 승인, 경리 지급, 전표(인사 필요) | 부서별 경비 추이 |

모듈은 어떤 조합으로도 동작합니다. 모듈끼리는 이벤트로만 만나므로, 한 모듈이 멈춰도 다른 모듈은 계속 일합니다. 플러그인도 같은 방식으로 SQL 파일 하나로 붙습니다([plugins/points.sql](plugins/points.sql)).

회계를 나중에 켜면 그 전의 청구와 입금으로 전표를 다시 만듭니다. 재고처럼 켜기 전의 일을 알 수 없는 것은 그렇다고 알려 줍니다.

## 연동

- **REST:** 유형마다 `/rest/v1/erp_api_<유형>` 이 자동으로 생깁니다. `If-Match` 와 `Idempotency-Key` 를 지원합니다.
- **MCP:** `/rest/v1/rpc/erp_mcp` 입니다. 별도 서버 없이 도구 4개(`erp_read`, `erp_create`, `erp_update`, `erp_delete`)로 켜져 있는 모듈의 레코드를 다룹니다. 에이전트가 MCP로 한 일은 같은 도구로 범위를 확인한 뒤 되돌릴 수 있습니다.
- **이벤트:** `erp_event_feed` 로 원장을 순서대로 읽습니다.

## 한계

- 메일 발송, 결제, 전자세금계산서, 은행 연동은 포함하지 않습니다. 필요하면 내 프로젝트의 Edge Function 으로 붙입니다.
- 무료 플랜의 500 MB 에는 다섯 모듈을 모두 켠 기준으로 이벤트 약 13만 건, 주문 약 1만 건이 들어갑니다(하루 주문 10건이면 약 3년). 자동 백업은 없으므로 원장을 내보내 두세요.
- 원장은 지울 수 없습니다. 연락처 같은 개인정보는 원장 밖에 두어 지울 수 있지만, 직원 이름과 입퇴사일, 구성원 계정의 메일은 원장에 남습니다. 주민등록번호는 받지 않습니다.
- 경비 영수증은 내 Supabase 프로젝트의 Storage 에 둡니다(무료 플랜 1 GB). 경비의 금액과 적요는 모든 구성원이 읽고, 파일은 관계된 사람만 엽니다.
- 모듈 사이는 최종 일관성입니다. 주문 확정 뒤 출고 전표가 생기기까지 짧은 지연이 있습니다.
- 예측과 what-if 의 정확도는 정답을 아는 가상 회사로 잰 것입니다. 실제 회사에서는 더 나쁠 수 있습니다.

## 개발

```bash
source scripts/local-env.sh
node scripts/build-sql.mjs && node --test --test-concurrency=4 test/*.test.mjs   # SQL
npm run test:e2e                                                                 # 브라우저
npm run web:dev                                                                  # :5301
```

구조는 [docs/architecture.md](docs/architecture.md), 흐름은 [docs/scenario.md](docs/scenario.md), 모듈 계약은 [docs/modules/](docs/modules/) 에 있습니다.
