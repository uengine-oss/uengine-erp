# E2E — erp-themes

테마는 화면만 바꾸므로 SQL 시험이 없다. 브라우저 시험 하나가 세 테마를 사람처럼 밟는다(설정 메뉴에서 고르고, 메뉴를 눌러 목록과 문서에 가고, 「다음 일」을 실행하고, 연결 지도의 줄을 눌러 다른 문서로 간다). 기본 테마가 그대로인지는 이 시험 하나가 아니라 **기존 브라우저 시험 전체**가 본다. 그 시험들은 테마를 고르지 않으므로 모두 기본으로 돈다.

```bash
# 저장소 루트에서. 브라우저는 로컬 스택의 postgres DB 를 초기화한다. 같은 스택을 함께 쓰면 잠금을 잡는다
source scripts/local-env.sh && npm --prefix web run build && lockf -t 1500 /tmp/uengine-erp-e2e.lock npx playwright test -c e2e/playwright.config.mjs e2e/tests/themes.spec.mjs

# 기본 테마 회귀: 브라우저 시험 전체
source scripts/local-env.sh && lockf -t 1500 /tmp/uengine-erp-e2e.lock npm run test:e2e
```

이 판의 출력은 `results/` 에 있다. `browser-themes.txt`(테마 시험 5 통과), `browser-all.txt`(브라우저 시험 전체 325 중 317 통과, 2 실패, 6 미실행), `browser-rerun-integration.txt`·`browser-rerun-whatif.txt`(떨어진 두 파일만 다시 돌려 3, 15 모두 통과), 그리고 시험이 찍은 화면 `330`~`338`.

전체 실행은 인쇄 시험을 더하기 전이라 테마 시험이 4개다. 떨어진 두 시험은 테마를 고르지 않는 기본 화면의 시험이다. 하나는 연동 키 창이 구성원 목록을 다 읽기 전에 열려 고를 사람이 없었고, 하나는 예측의 진행 표시가 시험이 보기 전에 지나갔다. 두 화면의 코드는 이번에 바뀌지 않았고, 같은 빌드로 다시 돌리면 통과한다.

## 이 시험이 보지 않는 것

- 색 대비를 숫자로 재지 않는다. 관제는 어두운 바탕과 밝은 글자인지만, 인쇄는 밝은 바탕과 어두운 글자인지만 본다.
- 세 테마에서 모든 화면을 열어 보지 않는다. 목록, 문서, 홈, 설정, 이벤트 원장만 연다. 모듈별 화면(간트, 달력, 차트)은 색 토큰을 따르지만 테마별로 찍어 확인하지 않았다.
- 홈 화면은 색과 간격만 테마를 따른다. 테마별로 다른 홈 배치는 만들지 않았다.
